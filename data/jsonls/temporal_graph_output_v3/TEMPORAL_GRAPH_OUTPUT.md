## Core Ontologies

### Node Ontology

- **Entity nodes**: domain entities such as organizations, products, technologies, events, locations, and people.
- **Date nodes**: normalized temporal anchors (year/date-like labels).
- **Tag nodes**: normalized topical labels derived from original row tags.

### Edge Ontology

- **Base edges (`edge_type=base`)**: original factual/graph relations from source rows.
- **Temporal hierarchy edges (`edge_type=inferred_temporal`)**:
  - `within_year`: date/range labels connected to contained year nodes.
  - `spans_year`: source entities/events linked to each year touched by their edge interval.
- **Entity hierarchy edges (`edge_type=inferred_entity`)**:
  - `entity_parent_of`: lexical parent-child relation (e.g., `Tesla` -> `Tesla Autopilot`).
- **Tag semantics edges (`edge_type=inferred_tag`)**:
  - `tag_related_to`: links tags to row entities with token overlap.

## Hierarchies Created

### 1) Temporal Hierarchy

- Normalizes heterogeneous time expressions to canonical forms where possible.
- Expands ranges (e.g., `1946–1948`) into all included years for hierarchy links.
- Connects precise timestamps/dates to broader year concepts.

### 2) Entity Hierarchy

- Uses simple robust lexical/stem rules to infer parent-child relations.
- Supports cases like org -> product/event/technology variants sharing root tokens.
- Supports demonym-like stems (e.g., `Latvian ...` potentially mapping under `Latvia`).

### 3) Tag-to-Concept Hierarchy

- Treats tags as first-class nodes.
- Normalizes tags into stable keys (slug form).
- Links tags to concept nodes via token overlap, enabling thematic clustering.

## JSONL Files (What is What)

### `processed_graph.jsonl`

One record per source row after ID remapping and node/edge/tag UID assignment.

Main fields:
- `id`: new graph row id (`<domain_prefix>_<positional_idx>`)
- `source_id`: original source row id
- `query`: query text
- `domain`: source domain field
- `tags` / `normalized_tags`: raw and normalized tags
- `node_uids`, `edge_uids`, `tag_uids`: references into global files

### `nodes.jsonl`

Global canonical node catalog (entities, dates, tags).

Main fields:
- `node_uid`: global node identifier
- `label`: display label
- `category`: ontology type (`event`, `org`, `date`, `tag`, ...)
- `normalized_label`: canonical text used for matching/dedup
- `source_count`, `source_row_ids`: provenance/support

### `edges.jsonl`

Global edge catalog containing both base and inferred hierarchy edges.

Main fields:
- `edge_uid`: global edge identifier
- `source_uid`, `target_uid`: node references
- `relation`: semantic relation label
- `start`, `end`: normalized temporal bounds when available
- `edge_type`: `base` or inferred hierarchy type
- `support_count`, `source_row_ids`: provenance/support

### `tags.jsonl`

Tag registry (also mirrored as `category=tag` entries in `nodes.jsonl`).

Main fields:
- `tag_uid`: global tag identifier
- `tag`: original tag text
- `normalized_tag`: canonical slug
- `source_count`, `source_row_ids`: provenance/support

### `build_report.json`

Machine-readable run summary used to keep this document's format stable while counts update per run.
